D3a — Preset Avatars: Core (implementation reference)

Precedence per the standing rule: the D3a prompt decisions outrank this file on behavior/ids/tokens. The original d3-avatar-v2.html ground-truth mockup was not present in the repo at build time, so this file documents the shipped D3a design (catalog ids, the picker layout, and the render sites) as a reference — it was authored to match the implementation, not the other way round. Glyphs below are emoji stand-ins for the placeholder SF Symbols; D-ART swaps custom emblems behind the same ids later. The rounded-square + white glyph here approximates the in-app AvatarView (which uses AdaptiveCardShapeStyle — pixel corners in the Pixel family, rounded in Clean).

WIRE CONTRACT

Two optional strings everywhere: avatarIcon: String? + avatarColor: String?. Default = sword + verdant. nil (either field) OR an unknown id ⇒ initials fallback at every render site, silently. Hex/gradient definitions NEVER enter Firestore. Rules validate type + size() < 40 only, never membership — the catalog grows with no rules change.

FALLBACK (nil / unknown id) — byte-preserved per site

Every existing user (no avatar) renders exactly today's initials view: the Profile header's gradient block, FriendProfileView's accent-tinted block, and the standings' rank-tinted initials avatar are each passed to AvatarView as its fallback verbatim — the diff is a no-op for nil data.
